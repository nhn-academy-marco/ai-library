## 1. 개요

동일한 질문이 반복될 때마다 AI를 호출하면 낭비입니다. 이전 결과를 저장했다가 재사용하면 비용을 절약하고 응답 속도를 높일 수 있습니다.

**이 문서에서 배울 내용:**
- 캐싱(Caching)이란 무엇인지
- 시맨틱 캐싱(Semantic Caching)이란 무엇인지
- 이벤트 기반 웜업(Warm-up) 전략
- 코사인 유사도를 활용한 캐시 매칭
- TTL(Time To Live) 정책

> **캐싱의 핵심** (설명을 위해 AI 호출 1회 비용을 $0.10으로 가정)
>
> **캐싱 없음:**
> - 질문: "자바 책 추천해줘"
> - 1번째: AI 호출 ($0.10)
> - 2번째: AI 호출 ($0.10)
> - 3번째: AI 호출 ($0.10)
> - 총비용: $0.30 (낭비)
>
> **캐싱 있음:**
> - 질문: "자바 책 추천해줘"
> - 1번째: AI 호출 → 캐시 저장 ($0.10)
> - 2번째: 캐시 사용 ($0.00)
> - 3번째: 캐시 사용 ($0.00)
> - 총비용: $0.10
>
> 약 67% 비용 절감

## 2. 핵심 개념 이해

### 2.1. 캐싱(Caching)이란?

자주 사용하는 데이터를 빠른 저장소에 두고 재사용하는 기술입니다.

**비유로 이해하기:**
```
[도서관에서 책 찾기]

캐싱 없음:
- 질문: "자바의 정석 어디 있어?"
- 1번째: 사서가 찾아봄 (5분)
- 2번째: 사서가 다시 찾아봄 (5분)
- 3번째: 사서가 또 찾아봄 (5분)
→ 매번 느림

캐싱 있음:
- 질문: "자바의 정석 어디 있어?"
- 1번째: 사서가 찾아봄 → 메모장에 위치 적음 (5분)
- 2번째: 메모장 보고 즉시 답변 (1초)
- 3번째: 메모장 보고 즉시 답변 (1초)
→ 2번째부터 빠름
```

### 2.2. 시맨틱 캐싱(Semantic Caching)

질문의 **의미**가 비슷하면 같은 질문으로 취급합니다.

**비교:**
```
[일반적인 캐싱 - 정확히 일치해야 함]
질문1: "자바 책 추천해줘"
질문2: "자바 책 추천해줘"
→ 캐시 적중

질문1: "자바 책 추천해줘"
질문2: "자바 교재 알려줘"
→ 캐시 미적중 (문자가 다름)

[시맨틱 캐싱 - 의미가 비슷하면 적중]
질문1: "자바 책 추천해줘"
질문2: "자바 책 추천해줘"
→ 캐시 적중

질문1: "자바 책 추천해줘"
질문2: "자바 교재 알려줘"
→ 캐시 적중 (의미가 비슷함)
질문3: "초보자용 자바 도서"
→ 캐시 적중 (의미가 비슷함)
```

**작동 원리:**
```
1. 질문 임베딩
   "자바 책 추천해줘" → [0.1, 0.2, ...]

2. 기존 캐시와 유사도 비교
   캐시1: "자바 책 추천" → [0.12, 0.18, ...]
   코사인 유사도: 0.99 → 매우 비슷함

3. 유사도가 임계값 이상이면 캐시 사용
   임계값: 0.98
   0.99 >= 0.98 → 캐시 적중
```

### 2.3. 이벤트 기반 웜업(Warm-up)

캐시가 없는 질문이 들어오면, 사용자에게는 빠른 결과를 먼저 보여 주고 AI 추천 결과는 백그라운드에서 미리 만들어 둡니다.

**비유로 이해하기:**
```
[레스토랑 준비]

웜업 없음:
- 손님: "스테이크 주문"
- 요리사: 바로 요리 시작 (20분)
→ 손님 오래 기다림

웜업 있음:
- 첫 손님: "스테이크 주문"
- 직원: 바로 나오는 샐러드를 먼저 서빙 (1분)
- 주방: 그사이 스테이크를 조리해서 보온 (백그라운드)
- 다음 손님: "스테이크 주문" → 즉시 서빙
→ 첫 손님도 기다리지 않고, 다음 손님은 바로 받음
```

**도서 검색에서의 웜업:**
```
사용자 A: "자바 책 추천" (캐시 Miss)
→ 하이브리드 검색 결과를 즉시 반환
→ BookSearchEvent 발행
→ 백그라운드(@Async)에서 AI 추천 생성 후 캐시 저장

사용자 B: "자바 책 추천" (캐시 Hit)
→ AI 추천이 포함된 결과를 즉시 응답 ✅
```

### 2.4. TTL (Time To Live)

캐시의 유효 기간입니다. 너무 오래된 캐시는 폐기합니다.

**비유로 이해하기:**
```
[유통기한이 있는 식품]

유통기한 없음:
- 1년 전 샌드위치 먹음
→ 배탈 날 수 있음

유통기한 있음:
- 1시간 전 샌드위치 먹음 (안전)
- 3일 전 샌드위치 폐기 (부적합)
```

**캐시에서의 TTL:**
```
TTL = 30분 (cache.ttl.minutes=30)

10:00 → 캐시 생성
10:20 → 캐시 사용 (20분 경과)
10:30 → 캐시 만료 (30분 경과)
10:31 → 다시 AI 호출해서 새 캐시 생성
```

## 3. 구현 가이드 (Step-by-Step)

> **실제 프로젝트 구현 구조**
>
> 시맨틱 캐시는 두 계층으로 구성됩니다.
> - **시맨틱 캐시 저장소**: `InMemoryBookSearchCacheRepository`(`ConcurrentHashMap` 기반). 질문 임베딩과 결과를 함께 저장하고 코사인 유사도로 비교합니다.
> - **로컬 캐시**: Spring Cache + Caffeine(`CacheConfig`)의 `bookSearchCache`. TTL 30분, 최대 500개입니다.
>
> `RedisConfig`는 `spring.data.redis.host`가 설정되어 있을 때 `RedisTemplate`만 등록하며, 시맨틱 캐시 저장에는 사용하지 않습니다.

### STEP 1: 캐시 객체와 저장소 정의

검색 결과를 저장할 캐시 객체와 저장소를 만듭니다. JPA 엔티티가 아니라 메모리에 보관하는 일반 객체입니다.

**BookSearchCache.java**
```java
package com.nhnacademy.library.core.book.domain;

import com.nhnacademy.library.core.book.dto.BookAiRecommendationResponse;
import com.nhnacademy.library.core.book.dto.BookSearchResponse;
import lombok.*;
import org.springframework.data.annotation.Id;

import java.util.List;

@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class BookSearchCache {
    @Id
    private String id;

    private String keyword;          // 검색 질문

    private float[] vector;          // 질문 임베딩 (시맨틱 매칭용)

    private List<BookSearchResponse> books;                 // 캐시된 검색 결과
    private List<BookAiRecommendationResponse> aiResponse;  // 캐시된 AI 추천 결과

    private long createdAt;          // 생성 시각 (epoch millis, TTL 계산용)
}
```

**BookSearchCacheRepository.java / InMemoryBookSearchCacheRepository.java**
```java
public interface BookSearchCacheRepository {
    BookSearchCache save(BookSearchCache cache);
    Iterable<BookSearchCache> findAll();
    void delete(BookSearchCache cache);
    void deleteAll();
}

@Repository
public class InMemoryBookSearchCacheRepository implements BookSearchCacheRepository {
    private final Map<String, BookSearchCache> cache = new ConcurrentHashMap<>();

    @Override
    public BookSearchCache save(BookSearchCache entry) {
        if (entry.getId() == null) {
            entry.setId(UUID.randomUUID().toString());
        }
        cache.put(entry.getId(), entry);
        return entry;
    }

    @Override
    public Iterable<BookSearchCache> findAll() {
        return cache.values();
    }

    @Override
    public void delete(BookSearchCache entry) {
        if (entry.getId() != null) {
            cache.remove(entry.getId());
        }
    }

    @Override
    public void deleteAll() {
        cache.clear();
    }
}
```

### STEP 2: 시맨틱 캐시 서비스 구현

코사인 유사도를 활용한 캐시 서비스를 만듭니다. 조회 시점에 TTL도 함께 확인합니다.

**SemanticCacheService.java**
```java
package com.nhnacademy.library.core.book.service.cache;

import com.nhnacademy.library.core.book.domain.BookSearchCache;
import com.nhnacademy.library.core.book.domain.SearchType;
import com.nhnacademy.library.core.book.dto.BookSearchRequest;
import com.nhnacademy.library.core.book.dto.BookSearchResult;
import com.nhnacademy.library.core.book.repository.BookSearchCacheRepository;
import com.nhnacademy.library.core.book.util.VectorUtils;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.cache.Cache;
import org.springframework.cache.CacheManager;
import org.springframework.data.domain.PageImpl;
import org.springframework.stereotype.Service;

import java.util.Optional;

/**
 * 의미적 캐싱 서비스
 */
@Slf4j
@Service
@RequiredArgsConstructor
public class SemanticCacheService {

    private final BookSearchCacheRepository cacheRepository;
    private final CacheManager cacheManager;

    @Value("${cache.ttl.minutes:30}")
    private int cacheTtlMinutes;

    private static final double SIMILARITY_THRESHOLD = 0.98;
    private static final long MILLIS_PER_MINUTE = 60 * 1000L;

    /**
     * 벡터 유사도 기반 캐시 조회
     */
    public Optional<BookSearchResult> findSimilarResult(BookSearchRequest request) {
        if (request.vector() == null) return Optional.empty();

        long ttlMillis = (long) cacheTtlMinutes * MILLIS_PER_MINUTE;
        long now = System.currentTimeMillis();

        for (BookSearchCache cached : cacheRepository.findAll()) {
            // 1. 코사인 유사도가 임계값(0.98) 미만이면 건너뜀
            double similarity = VectorUtils.calculateCosineSimilarity(request.vector(), cached.getVector());
            if (similarity < SIMILARITY_THRESHOLD) continue;

            // 2. TTL이 지난 캐시는 삭제하고 건너뜀
            long age = now - cached.getCreatedAt();
            if (age > ttlMillis || age < 0) {
                evictCache(cached);
                continue;
            }

            // 3. 캐시 적중
            log.info("[SEMANTIC_CACHE] Found similar request in cache: '{}' (Similarity: {})",
                    cached.getKeyword(), similarity);
            return Optional.of(BookSearchResult.builder()
                    .books(new PageImpl<>(cached.getBooks()))
                    .aiResponse(cached.getAiResponse())
                    .createdAt(cached.getCreatedAt())
                    .build());
        }
        return Optional.empty();
    }

    /**
     * 캐시 저장 (RAG 검색 결과만 저장)
     */
    public void save(BookSearchRequest request, BookSearchResult result) {
        if (request.searchType() != SearchType.RAG) return;

        BookSearchCache cacheEntry = BookSearchCache.builder()
                .keyword(request.keyword())
                .vector(request.vector())
                .books(result.getBooks().getContent())
                .aiResponse(result.getAiResponse())
                .createdAt(result.getCreatedAt())
                .build();
        cacheRepository.save(cacheEntry);

        // Spring Cache(Caffeine 로컬 캐시)에도 저장
        Cache cache = cacheManager.getCache("bookSearchCache");
        if (cache != null) {
            cache.put(request, result);
        }
    }

    private void evictCache(BookSearchCache cached) {
        cacheRepository.delete(cached);
        // Caffeine 로컬 캐시에서도 Warm-up 키와 일반 사용자 키를 모두 제거
        // (생략)
    }
}
```

> 코사인 유사도 계산은 `VectorUtils.calculateCosineSimilarity()`가 담당합니다. 결과 범위는 -1.0(반대 방향) ~ 1.0(같은 방향)입니다.

### STEP 3: 이벤트 기반 웜업 구현

캐시 Miss가 발생하면 사용자에게는 하이브리드 검색 결과를 먼저 돌려주고, AI 추천 생성은 이벤트로 백그라운드에 넘깁니다.

**BookSearchEvent.java**
```java
@Getter
public class BookSearchEvent extends ApplicationEvent {
    private final String keyword;

    public BookSearchEvent(Object source, String keyword) {
        super(source);
        this.keyword = keyword;
    }
}
```

**BookSearchEventListener.java**
```java
@Slf4j
@Component
@RequiredArgsConstructor
public class BookSearchEventListener {

    private final BookSearchCacheService bookSearchCacheService;

    @Async
    @EventListener
    public void handleBookSearchEvent(BookSearchEvent event) {
        log.info("[EVENT_LISTENER] Received search event for keyword: {}", event.getKeyword());
        bookSearchCacheService.warmUpRagCache(event.getKeyword());
    }
}
```

**BookSearchCacheService.java**
```java
@Slf4j
@Service
@RequiredArgsConstructor
public class BookSearchCacheService {

    private final ApplicationContext applicationContext;
    private final SemanticCacheService semanticCacheService;
    private final Set<String> inFlightWarmUps = ConcurrentHashMap.newKeySet();

    @Async
    public void warmUpRagCache(String keyword) {
        if (keyword == null || keyword.isBlank()) return;
        // 같은 키워드의 웜업이 이미 진행 중이면 건너뜀
        if (!inFlightWarmUps.add(keyword)) return;

        try {
            // 순환 참조를 피하기 위해 ApplicationContext에서 지연 조회
            BookSearchService bookSearchService = applicationContext.getBean(BookSearchService.class);
            EmbeddingService embeddingService = applicationContext.getBean(EmbeddingService.class);

            // 1. 임베딩 생성 후 Warm-up 요청(isWarmUp = true) 구성
            float[] vector = embeddingService.getEmbedding(keyword);
            BookSearchRequest ragRequest = new BookSearchRequest(keyword, null, SearchType.RAG, vector, true);

            // 2. 이미 유사한 캐시가 있으면 종료
            if (semanticCacheService.findSimilarResult(ragRequest).isPresent()) {
                return;
            }

            // 3. RAG 검색 수행 → RagSearchStrategy가 AI 추천을 생성하고 캐시에 저장
            bookSearchService.searchBooks(PageRequest.of(0, 24), ragRequest);
        } catch (Exception e) {
            log.error("[STRATEGIC_CACHE] Failed to warm up RAG cache for keyword: {}", keyword, e);
        } finally {
            inFlightWarmUps.remove(keyword);
        }
    }
}
```

### STEP 4: RAG 검색 전략에 캐싱 적용

`RagSearchStrategy`에서 캐시를 확인하고, 결과를 캐시에 저장합니다.

**RagSearchStrategy.java (발췌)**
```java
@Override
public BookSearchResult search(Pageable pageable, BookSearchRequest request) {
    // 1. 일반 사용자 요청: 캐시 조회
    if (!request.isWarmUp()) {
        Optional<BookSearchResult> cachedResult = semanticCacheService.findSimilarResult(request);
        if (cachedResult.isPresent()) {
            return cachedResult.get();   // 캐시 Hit
        }

        // 캐시 Miss: 하이브리드 결과를 먼저 반환하고, AI 추천은 백그라운드(Warm-up)로 위임
        eventPublisher.publishEvent(new BookSearchEvent(this, request.keyword()));
        return hybridSearchStrategy.search(pageable, request);
    }

    // 2. Warm-up 요청: 하이브리드 검색 → Top-K 선택 → AI 추천 생성 → LLM 검증 반영
    // ... (02. Top-K 최적화 참고)

    // 3. 생성된 결과를 시맨틱 캐시에 저장
    semanticCacheService.save(request, finalResult);
    return finalResult;
}
```

### STEP 5: TTL 정책 구현

별도의 스케줄러 없이 두 가지 방식으로 TTL을 적용합니다.

1. **시맨틱 캐시 저장소**: `findSimilarResult()`가 조회 시점에 `createdAt`을 확인해 30분이 지난 항목을 삭제합니다(STEP 2 참고).
2. **Caffeine 로컬 캐시**: `expireAfterWrite`로 쓰기 후 30분이 지나면 자동으로 만료되고, `maximumSize`로 최대 500개까지만 보관합니다.

**application.properties**
```properties
# Cache TTL in minutes (default 30 min)
cache.ttl.minutes=30
# Book search cache settings
cache.book-search.ttl.minutes=30
cache.book-search.max-size=500
```

**CacheConfig.java (발췌)**
```java
@EnableCaching
@Configuration
public class CacheConfig {

    @Value("${cache.book-search.ttl.minutes:30}")
    private int bookSearchTtlMinutes;

    @Value("${cache.book-search.max-size:500}")
    private int bookSearchMaxSize;

    @Bean
    @Primary
    public CacheManager cacheManager() {
        CaffeineCacheManager cacheManager = new CaffeineCacheManager();
        cacheManager.setCacheNames(List.of("bookSearchCache", "reviewSummaries" /* ... */));

        // 기본 Caffeine 설정 (도서 검색 및 리뷰 캐시용)
        cacheManager.setCaffeine(Caffeine.newBuilder()
            .expireAfterWrite(bookSearchTtlMinutes, TimeUnit.MINUTES)
            .maximumSize(bookSearchMaxSize)
            .recordStats()); // 통계 활성화

        return cacheManager;
    }
}
```

## 4. 최적화 전략

### 4.1. 캐시 적중률 최적화

**캐시 적중률(Cache Hit Rate):**
```
캐시 적중률 = (캐시 적중 횟수 / 전체 요청 수) × 100%

예시:
- 전체 요청: 100회
- 캐시 적중: 70회
- 캐시 적중률: 70%
```

**최적화 방법:**

| 방법 | 설명 | 효과 |
|------|------|------|
| 웜업 | 캐시 Miss 질문을 백그라운드에서 미리 캐시 | 다음 요청부터 적중 |
| 임계값 조정 | 유사도 기준을 낮춤 | 더 많은 적중 |
| TTL 연장 | 캐시 유효 기간 늘림 | 재계산 감소 |

### 4.2. 메모리 관리

너무 많은 캐시는 메모리 문제를 일으킬 수 있습니다.

**LRU (Least Recently Used) 전략:**
```
[캐시 사용 패턴]
캐시 A: 10분 전에 마지막 접근
캐시 B: 1분 전에 마지막 접근
캐시 C: 5분 전에 마지막 접근

[메모리 부족 시]
→ 캐시 A 삭제 (가장 오래된 것)
→ 최근에 자주 사용하는 캐시 유지
```

**실제 프로젝트:**
- Caffeine 로컬 캐시는 `maximumSize(500)`으로 개수를 제한합니다. Caffeine은 LRU를 개선한 W-TinyLFU 알고리즘으로 제거 대상을 고릅니다.
- `InMemoryBookSearchCacheRepository`에는 개수 제한이 없고, 만료된 항목은 조회 시점에만 삭제됩니다. 운영 환경에서는 최대 크기나 주기적 정리를 추가하는 것을 고려하세요.

### 4.3. 비용 절감 효과

**비교:**
```
[캐싱 없음]
일일 요청: 1,000회
1회당 비용: $0.10
일일 비용: $100

[캐싱 있음 (적중률 70%)]
일일 요청: 1,000회
- 캐시 적중: 700회 × $0.00 = $0
- AI 호출: 300회 × $0.10 = $30
일일 비용: $30

절감: $70/일 (70%)
월간 절감: $2,100
```

### 미션 1: 시맨틱 캐시 테스트

```java
@Test
void testSemanticCache() {
    String query1 = "자바 책 추천";
    String query2 = "자바 교재 알려줘";  // 비슷한 의미

    BookSearchRequest request1 = new BookSearchRequest(
            query1, null, SearchType.RAG, embeddingService.getEmbedding(query1));
    BookSearchRequest request2 = new BookSearchRequest(
            query2, null, SearchType.RAG, embeddingService.getEmbedding(query2));

    // 1번째 요청 - 캐시 Miss
    assertTrue(semanticCacheService.findSimilarResult(request1).isEmpty());

    // 캐시에 저장
    BookSearchResult result = new BookSearchResult(new PageImpl<>(List.of()), List.of());
    semanticCacheService.save(request1, result);

    // 2번째 요청 - 유사도가 0.98 이상이면 캐시 Hit
    Optional<BookSearchResult> cached = semanticCacheService.findSimilarResult(request2);
    log.info("캐시 적중 여부: {}", cached.isPresent());
}
```

> 임계값이 0.98로 높기 때문에 표현이 꽤 다른 질문은 Miss가 날 수 있습니다. 여러 질문 쌍으로 유사도를 직접 확인해 보세요.

### 미션 2: 코사인 유사도 계산

```java
@Test
void testCosineSimilarity() {
    float[] v1 = {1.0f, 2.0f, 3.0f};
    float[] v2 = {1.0f, 2.0f, 3.0f};  // 완전히 같음
    float[] v3 = {-1.0f, -2.0f, -3.0f};  // 반대 방향

    double sim1 = VectorUtils.calculateCosineSimilarity(v1, v2);
    double sim2 = VectorUtils.calculateCosineSimilarity(v1, v3);

    assertEquals(1.0, sim1, 0.001);  // 같은 방향
    assertEquals(-1.0, sim2, 0.001);  // 반대 방향
}
```

### 미션 3: TTL 정책 테스트

@Test
void testTtl() {
    float[] vector = {1.0f, 2.0f, 3.0f};
    BookSearchRequest request = new BookSearchRequest("test", null, SearchType.RAG, vector);
