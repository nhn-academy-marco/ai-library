# 06. 피드백 기반 검색 개선 설계

> 모은 피드백을 검색 순위와 LLM 프롬프트에 직접 반영하는 방법을 설계합니다. 피드백 점수를 보너스로 더할 때의 함정(점수 범위, 표본 수, 편향)과, 프롬프트에 피드백을 넣을 때 "관련성 우선, 피드백은 참고"를 지키는 이유를 이해합니다.
>
> 예상 소요 시간: 1시간 · 난이도: 심화

## 학습 목표

- 도서 단위 집계와 (검색어, 도서) 단위 집계의 장단점을 비교할 수 있다
- 피드백 보너스의 크기를 원래 점수의 범위에 맞춰 정해야 하는 이유를 설명할 수 있다
- 최소 피드백 수 기준이 필요한 이유를 표본 크기 관점에서 설명할 수 있다
- 기존 RAG 프롬프트의 "리뷰 정보 반영" 규칙과 같은 방식으로 피드백 규칙을 설계할 수 있다

## 시작하기 전에

- [05. 피드백 루프 완성](05.feedback-search-integration.md)에서 피드백이 Step 6 개인화로 이어지는 경로를 확인했어야 합니다.
- RRF(Reciprocal Rank Fusion)는 [Step 2. 하이브리드 검색](../step-2/05.hybrid-search.md), 리뷰를 프롬프트에 넣는 방식은 [Step 4. 리뷰 정보를 RAG 검색에 반영하기](../step-4/05.review-rag-integration.md)를 참고하세요.
- 용어는 [용어집](../glossary.md)을 참고하세요.

> 이 문서는 **설계 가이드**입니다. 피드백 보너스 재정렬과 프롬프트의 피드백 규칙은 현재 소스에 구현되어 있지 않습니다. 이 프로젝트가 실제로 피드백을 검색에 반영하는 방법은 Step 6의 사용자 선호 벡터(개인화)입니다. 여기서 다루는 내용은 실습 미션이나 확장 과제로 활용하세요.

## 1. 왜 필요한가

Step 6의 개인화는 **사용자 한 명**의 취향을 반영합니다. 철수가 판타지에 👍를 많이 눌렀다면 철수의 검색 결과에서 판타지가 올라갑니다. 그런데 다음과 같은 경우는 해결하지 못합니다.

- "해리포터"를 검색한 사람 100명 중 90명이 『해리포터 영화 메이킹북』에 👎를 눌렀습니다. 그래도 처음 검색하는 101번째 사용자에게는 여전히 1위로 나옵니다.
- 피드백이 하나도 없는 새 사용자는 콜드 스타트라 개인화 효과가 없습니다.

**모든 사용자의 피드백을 모아(집단 피드백)** 검색 순위와 LLM 판단에 반영하면 이 문제를 줄일 수 있습니다. 다만 잘못 설계하면 오히려 검색 품질을 망칩니다. 이 문서는 그 함정을 피하는 방법을 다룹니다.

## 2. 핵심 개념

### 2.1 무엇을 기준으로 모을까

| 구분 | 도서(book_id) 단위 | (검색어, 도서) 단위 |
|------|-------------------|---------------------|
| 예 | 101번 도서의 전체 👍/👎 | "해리포터"로 찾았을 때 101번 도서의 👍/👎 |
| 장점 | 데이터가 빨리 쌓임 | 검색 의도를 반영함 |
| 단점 | 검색어 맥락을 무시함 | 같은 검색어가 반복돼야 효과가 있음 |
| 쓰는 Repository 메서드 | `findByBookId` | `findByQueryAndBookId` |

도서 단위는 "이 책이 대체로 좋은 책인가"를, (검색어, 도서) 단위는 "이 검색어에 이 책이 맞는 답인가"를 측정합니다. 03 문서에서 피드백에 검색어를 함께 저장한 덕분에 두 방식 모두 가능합니다.

### 2.2 피드백 점수와 보너스

03 문서에서 만든 피드백 점수를 그대로 씁니다.

```text
피드백 점수 = (긍정 수 - 부정 수) / 전체 수      범위: -1.0 ~ +1.0

도서 A: 👍 15, 👎 2  → (15 - 2) / 17 = +0.76
도서 B: 👍 5,  👎 5  → (5 - 5) / 10  =  0.00
도서 C: 👍 2,  👎 8  → (2 - 8) / 10  = -0.60
```

이 점수를 원래 검색 점수에 더하거나 곱해 순위를 다시 매기는 것을 **재정렬(Reranking)** 이라고 합니다.

### 2.3 함정 1: 점수의 크기(스케일)

"피드백 점수 × 0.5를 더한다"는 규칙은 원래 점수가 0~100 범위일 때는 작은 보정입니다. 75점이 75.5점이 될 뿐입니다. 그런데 이 프로젝트의 하이브리드 검색 점수인 RRF(k=60)는 한 도서가 받을 수 있는 값이 대략 0.03 안팎입니다.

| 도서 | RRF 점수 | 피드백 점수 | +피드백×0.5 | 결과 |
|------|----------|-------------|-------------|------|
| A | 0.033 | -0.2 | 0.033 - 0.1 = -0.067 | 3위 |
| B | 0.030 | +0.4 | 0.030 + 0.2 = 0.230 | 1위 |
| C | 0.016 | +0.2 | 0.016 + 0.1 = 0.116 | 2위 |

보너스가 원래 점수보다 수십 배 커서, 검색 관련성은 사라지고 **피드백이 순위를 전부 결정**합니다. 보너스는 원래 점수의 범위에 맞춰야 합니다.

```text
나쁜 예: 최종 점수 = RRF + 피드백 점수 × 0.5          (스케일 무시)
좋은 예: 최종 점수 = RRF × (1 + α × 피드백 점수)      (α = 0.1 ~ 0.3, 원래 점수의 ±10~30% 안에서 조정)
```

곱셈 방식은 원래 점수가 클수록 보정도 커지므로, 관련성이 낮은 도서가 피드백만으로 1위에 오르는 일을 막아 줍니다. Step 6의 개인화 점수(`rrfScore + similarity × 0.3`, similarity는 0~1)를 공부할 때도 같은 관점, 즉 "더하는 값이 원래 점수에 비해 얼마나 큰가"로 살펴보세요.

### 2.4 함정 2: 표본이 너무 적을 때

👍 1건, 👎 0건인 도서의 피드백 점수는 +1.0으로, 👍 92건, 👎 8건(+0.84)인 도서보다 높습니다. 한 사람의 클릭이 수십 명의 평가를 이기는 셈입니다. 그래서 **최소 피드백 수** 기준을 둡니다.

| 집계 단위 | 권장 최소 건수(예) | 이유 |
|-----------|-------------------|------|
| 도서 단위 | 5건 | 데이터가 빨리 쌓이므로 기준을 높게 |
| (검색어, 도서) 단위 | 3건 | 조합이 잘게 나뉘어 데이터가 적으므로 기준을 낮게 |
| 개인화(Step 6, 실제 구현) | GOOD 3권 | `app.personalization.min-feedback-count=3` |

기준 미만이면 보너스를 0으로 둡니다. 숫자는 데이터 양을 보며 조정하는 **설계 값**이지 정답이 아닙니다.

### 2.5 함정 3: 부익부 편향

상위에 노출된 도서만 피드백을 받고, 피드백을 받은 도서가 다시 상위에 오르면 신간이나 하위 도서는 영영 기회를 얻지 못합니다. 이를 **인기 편향(Popularity Bias)** 이라고 합니다. 보너스 상한을 두고, 피드백이 없는 도서는 0(중립)으로 취급해 불이익을 주지 않아야 합니다.

## 3. 예제로 이해하기

### 3.1 (검색어, 도서) 단위 피드백 점수 계산

`SearchFeedbackRepository.findByQueryAndBookId`는 이미 소스에 있습니다. 이를 이용한 점수 계산은 다음과 같이 설계할 수 있습니다.

```java
private static final int MIN_FEEDBACK_COUNT = 3;

public double calculateQueryFeedbackScore(String query, Long bookId) {
    List<SearchFeedback> feedbacks = searchFeedbackRepository.findByQueryAndBookId(query, bookId);

    // 표본이 부족하면 중립(0)
    if (feedbacks.size() < MIN_FEEDBACK_COUNT) {
        return 0.0;
    }
    return FeedbackStats.from(feedbacks).feedbackScore();   // -1.0 ~ +1.0
}
```

```java
private static final double FEEDBACK_WEIGHT = 0.2;   // 원래 점수의 ±20% 범위에서 조정

public double applyFeedback(double rrfScore, double feedbackScore) {
    return rrfScore * (1 + FEEDBACK_WEIGHT * feedbackScore);
}
```

- 기존 `FeedbackStats.from`을 재사용해 계산 규칙을 한곳에 둡니다.
- 검색 결과 5건마다 쿼리를 한 번씩 보내면 N+1 문제가 생깁니다. 실제로 구현한다면 검색어 하나에 대해 `GROUP BY book_id`로 한 번에 집계하는 쿼리(03 문서 미션 3)를 쓰는 편이 좋습니다.

예시("해리포터" 검색, `FEEDBACK_WEIGHT = 0.2`):

| 도서 | RRF 점수 | 피드백(👍/👎) | 피드백 점수 | 최종 점수 | 순위 변화 |
|------|----------|---------------|-------------|-----------|-----------|
| 메이킹북 | 0.0328 | 1 / 9 | -0.80 | 0.0328 × 0.84 = 0.0276 | 1위 → 3위 |
| 마법사의 돌 | 0.0315 | 12 / 1 | +0.85 | 0.0315 × 1.17 = 0.0369 | 2위 → 1위 |
| 비밀의 방 | 0.0301 | 1 / 0 | 0 (표본 부족) | 0.0301 | 3위 → 2위 |

관련성이 비슷한 도서 사이에서만 순서가 바뀌고, 관련성이 크게 낮은 도서를 끌어올리지는 않습니다.

### 3.2 프롬프트에 피드백 정보 넣기

RAG의 LLM 프롬프트(`AiRecommendationService`)는 이미 Step 4에서 **평점과 리뷰 수**를 도서 데이터에 넣고, 별도의 규칙 블록으로 해석 방법을 알려 줍니다.

```text
[규칙 - 리뷰 정보 반영]
- 평점과 리뷰 수를 relevance 점수에 반영하세요:
  - 평점 4.5 이상 + 리뷰 20개 이상: relevance +5점 (검증된 인기 도서)
  - 평점 4.0 이상 + 리뷰 20개 이상: relevance +3점 (검증된 도서)
  - 평점 3.5 미만: relevance -10점 (부정적 평가)
  - 리뷰 없음: relevance ±0점 (변동 없음)
...
- 리뷰가 없는 신간 도서는 "신간 도서로 아직 리뷰가 없습니다"라고 언급하고, 최신성과 내용의 관련성을 더 중요하게 평가하세요.
```

피드백도 같은 패턴으로 넣을 수 있습니다. 두 가지를 바꿉니다.

**(1) 도서 데이터에 피드백 요약 추가**

```text
ID: 101, 제목: 해리포터와 마법사의 돌, 저자: J.K. 롤링, 평점: 4.8/5.0(127개 리뷰), 피드백: 긍정 92건/부정 8건(92%), 출판일: 2020-01-01, 내용: ...
ID: 104, 제목: 해리포터 영화 메이킹북, 저자: ..., 출판일: 2024-01-15, 내용: ...
```

```java
// 설계 예시: BookSearchResponse에 FeedbackStats를 담는 필드를 추가했다고 가정
private String formatFeedbackInfo(FeedbackStats stats) {
    if (stats == null || stats.totalCount() < 5) {
        return "";   // 표본이 적으면 넣지 않음 (평점 정보와 같은 방식)
    }
    return String.format("피드백: 긍정 %d건/부정 %d건(%.0f%%)",
            stats.goodCount(), stats.badCount(), stats.goodRatio() * 100);
}
```

**(2) 해석 규칙 블록 추가**

```text
[규칙 - 사용자 피드백 반영]
- relevance는 query와 도서 내용의 관련성을 최우선 기준으로 매기세요.
- 피드백 정보는 참고 자료로만 사용하고, relevance 조정 폭은 ±5점 이내로 하세요.
  - 긍정 80% 이상: relevance +5점 (사용자들이 만족한 도서)
  - 긍정 20% 미만: relevance -5점 (부정적 평가가 많은 도서)
- 피드백 정보가 없는 도서는 불이익 없이 내용의 관련성만으로 평가하세요.
```

### 3.3 프롬프트 문구가 결과를 바꾼다

LLM은 지시를 말 그대로 따르는 경향이 있습니다. 강한 표현을 쓰면 다른 기준을 무시합니다.

| 항목 | 피해야 할 표현 | 권장 표현 | 이유 |
|------|---------------|-----------|------|
| 우선순위 | "피드백이 높은 도서를 무조건 상위에" | "관련성을 최우선으로, 피드백은 참고" | LLM이 relevance 판단을 포기하고 피드백 순으로 정렬함 |
| 피드백 없는 도서 | "피드백 없는 도서는 제외" | "불이익 없이 내용으로 평가" | 신간이 영영 노출되지 않음(인기 편향) |
| 조정 폭 | "피드백을 반영하세요" | "±5점 이내로 조정" | 범위가 없으면 LLM마다, 호출마다 반영 정도가 들쭉날쭉함 |
| 단정 표현 | "반드시", "항상", "절대" | "고려", "참고" | 다른 규칙(관련성, 출간일)과 충돌할 때 한쪽만 따름 |

리뷰 규칙의 조정 폭(+5, +3, -10)과 피드백 규칙의 조정 폭을 비슷한 크기로 맞추는 것도 중요합니다. 한 신호만 지나치게 크면 LLM이 그 신호에만 반응합니다.

## 4. 직접 해 보기

### 미션 1 (기본): 스케일 계산

RRF 점수가 0.032와 0.018인 두 도서가 있습니다. 두 번째 도서의 피드백 점수가 +1.0, 첫 번째는 0일 때, (a) `RRF + 피드백 × 0.5`와 (b) `RRF × (1 + 0.2 × 피드백)` 방식의 순위를 각각 구하세요.

<details>
<summary>정답</summary>

- (a) 첫 번째 0.032, 두 번째 0.018 + 0.5 = 0.518 → 두 번째가 1위. 관련성 차이를 피드백이 완전히 뒤집습니다.
- (b) 첫 번째 0.032, 두 번째 0.018 × 1.2 = 0.0216 → 첫 번째가 1위 유지. 관련성 차이가 크면 피드백만으로는 뒤집히지 않습니다.

</details>

### 미션 2 (기본): 최소 건수 판단

다음 중 보너스를 적용할 대상은 무엇입니까? (검색어+도서 단위, 최소 3건 기준)

- 도서 X: 👍 2, 👎 0
- 도서 Y: 👍 2, 👎 1
- 도서 Z: 👍 0, 👎 4

<details>
<summary>정답</summary>

Y(3건, 점수 +0.33)와 Z(4건, 점수 -1.0)만 적용합니다. X는 2건이라 점수가 +1.0이어도 표본 부족으로 0(중립)입니다.

</details>

### 미션 3 (도전): 시간 감쇠

1년 전의 👍와 어제의 👍를 같은 무게로 세는 것이 적절할까요? 최근 피드백에 더 큰 가중치를 주는 계산 방법을 설계해 보세요.

<details>
<summary>예시 답안</summary>

피드백마다 경과 일수 `d`에 따라 가중치 `w = 0.5^(d / 30)`(반감기 30일)을 주고, `(Σ w_good - Σ w_bad) / Σ w`로 점수를 계산합니다. 30일 전 피드백은 절반, 60일 전은 4분의 1 무게가 됩니다. 도서 내용은 변하지 않지만 검색 엔진과 데이터가 바뀌므로, 오래된 피드백이 지금의 결과 품질을 대표하지 않을 수 있습니다. 반감기를 너무 짧게 잡으면 표본이 줄어드는 문제와 함께 고려해야 합니다.

</details>

## 5. 자주 하는 실수

| 증상 | 원인 | 해결 |
|------|------|------|
| 관련 없는 도서가 1위로 올라옴 | 보너스가 원래 점수보다 훨씬 큼(스케일 불일치) | 곱셈 방식이나 정규화로 원래 점수의 일정 비율 안에서만 조정합니다 |
| 피드백 1~2건짜리 도서가 상위 독점 | 최소 피드백 수 기준 없음 | 기준 미만이면 0(중립)으로 둡니다 |
| 신간이 검색 결과에 거의 안 나옴 | 피드백 없는 도서에 불이익, 인기 편향 | 피드백 없음을 중립으로 처리하고 보너스 상한을 둡니다 |
| LLM이 관련성 낮은 도서를 추천 | 프롬프트에 "무조건", "반드시" 같은 강한 피드백 지시 | "관련성 우선, 피드백 참고"와 조정 폭(±5점)을 명시합니다 |
| 검색이 느려짐 | 도서마다 피드백 쿼리(N+1) | 검색어 하나에 대해 `GROUP BY book_id`로 한 번에 집계합니다 |

## 6. 정리

- 피드백은 도서 단위(빨리 쌓임)와 (검색어, 도서) 단위(검색 의도 반영)로 모을 수 있습니다.
- 보너스는 원래 점수의 크기에 맞춰야 합니다. RRF처럼 작은 점수에 고정값을 더하면 피드백이 순위를 전부 결정합니다.
- 표본이 적은 피드백은 반영하지 않고, 피드백이 없는 도서는 중립으로 둡니다.
- 프롬프트에는 "관련성 우선, 피드백 참고"와 구체적인 조정 폭을 적고, 기존 리뷰 규칙과 크기를 맞춥니다.
- 이 프로젝트에서 실제로 구현된 피드백 활용은 Step 6의 개인화이며, 이 문서의 설계는 확장 과제입니다.

- [ ] 도서 단위와 (검색어, 도서) 단위 집계의 차이를 설명할 수 있다
- [ ] RRF 점수에 ±0.5 보너스를 더하면 안 되는 이유를 계산으로 보일 수 있다
- [ ] 피드백 규칙 블록을 기존 리뷰 규칙과 같은 형식으로 작성할 수 있다

## 확인 문제

**1. 👍 1건만 받은 도서의 피드백 점수가 👍 92건, 👎 8건인 도서보다 높게 나오는 문제를 무엇으로 막습니까?**

<details><summary>정답</summary>

최소 피드백 수 기준입니다. 일정 건수 미만이면 점수를 0(중립)으로 두어, 표본이 적은 우연한 평가가 순위에 영향을 주지 않게 합니다.

</details>

**2. 0~100점 체계에서 적절했던 "피드백 × 0.5 보너스"를 RRF 점수에 그대로 쓰면 어떻게 됩니까?**

<details><summary>정답</summary>

RRF 점수는 0.03 안팎이라 ±0.5 보너스가 원래 점수보다 수십 배 큽니다. 관련성과 무관하게 피드백이 순위를 결정하게 되므로, 원래 점수에 비례하는 방식(예: `RRF × (1 + α × 피드백 점수)`)으로 바꿔야 합니다.

</details>

**3. 프롬프트에 "피드백이 없는 도서는 추천하지 마세요"라고 쓰면 어떤 문제가 생깁니까?**

<details><summary>정답</summary>

신간이나 아직 노출되지 않은 도서는 피드백을 받을 기회 자체가 없어 영영 추천되지 않습니다. 피드백을 받은 도서만 계속 노출되는 인기 편향이 강해집니다.

</details>

**4. Step 6의 개인화와 이 문서의 집단 피드백 반영은 무엇이 다릅니까?**

<details><summary>정답</summary>

개인화는 한 사용자의 👍 도서로 그 사용자만의 선호 벡터를 만들어 그 사용자의 결과만 바꿉니다. 집단 피드백 반영은 모든 사용자의 피드백을 도서 또는 (검색어, 도서) 단위로 모아 모든 사용자의 결과에 반영합니다. 그래서 피드백이 없는 새 사용자에게도 효과가 있습니다.

</details>
