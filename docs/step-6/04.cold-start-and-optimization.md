# Phase 4: 콜드 스타트와 성능 최적화

## 학습 개요

개인화 추천 시스템의 실제 운영 환경에서 발생하는 제약사항과 해결 방안을 학습합니다. 콜드 스타트 문제, 성능 병목, 익명 사용자 환경의 한계 등을 분석하고 이를 극복하는 전략을 설계합니다.

## 학습 목표

1. **콜드 스타트(Cold Start) 문제 이해**
   - 신규 사용자의 개인화 불가 문제
   - 전체 인기도 반영 전략
   - 피드백 수집 유도 방법

2. **성능 최적화 전략**
   - 선호도 벡터 캐싱 (Caffeine)
   - 비동기 계산으로 응답 시간 단축
   - 배치 처리로 DB 부하 감소

3. **익명 사용자 환경 제약사항**
   - Telegram chatId의 한계와 해결
   - 세션 기반 개인화의 범위 이해
   - 데이터 보호와 정리 정책

## 1. 콜드 스타트(Cold Start) 문제

### 1.1 문제 정의

**콜드 스타트(Cold Start):** 신규 사용자에게 개인화된 추천을 제공할 수 없는 문제

```
신규 사용자 등록
    ↓
피드백 기록: 0개
    ↓
선호도 벡터: null
    ↓
개인화: 불가능 (일반 검색 결과만 제공)
```

### 1.2 해결 전략 1: 최소 피드백 수 요구

**현재 접근:**
```java
if (likedBookIds.size() < 3) {
    // 개인화 미적용
    return null;
}
```

**장점:**
- 신뢰할 수 있는 선호도 벡터 생성
- 노이즈 감소

**단점:**
- 피드백이 1~2개인 사용자에게는 개인화 미제공
- 피드백 수집 유도 필요

### 1.3 해결 전략 2: 전체 인기도 반영

**아이디어:** 신규 사용자에게 전체 인기 도서를 추천

> 이 전략과 2.4의 배치 처리는 현재 소스에 구현되어 있지 않은 **확장 예시**입니다. 직접 구현할 때 참고하세요.

```java
public float[] calculateUserPreferenceVector(Long chatId) {
    List<Long> likedBookIds = getLikedBookIds(chatId);

    // [콜드 스타트 대안] 전체 인기 도서의 평균 벡터 사용
    if (likedBookIds.size() < minFeedbackCount) {
        log.info("Cold start: using global popularity vector");
        return getGlobalPopularityVector();
    }

    // ... 기존 로직
}

/**
 * 전체 사용자의 GOOD 피드백이 많은 도서들의 평균 벡터
 */
private float[] getGlobalPopularityVector() {
    // 캐싱된 전체 인기 벡터 반환 (없으면 null → 개인화 미적용)
    Cache cache = cacheManager.getCache("globalPopularity");
    return cache != null ? cache.get("vector", float[].class) : null;
}
```

**전체 인기 벡터 계산:**
```java
// SearchFeedbackRepository에 추가할 메서드
@Query("SELECT sf.bookId FROM SearchFeedback sf WHERE sf.type = :type " +
       "GROUP BY sf.bookId ORDER BY COUNT(sf) DESC")
List<Long> findMostPopularBooks(@Param("type") FeedbackType type, Pageable pageable);
```

```java
/**
 * 전체 인기 벡터를 계산하고 캐싱합니다.
 * 주기적으로 (예: 매일 새벽) 갱신합니다.
 */
@Scheduled(cron = "0 0 3 * * ?")  // 매일 새벽 3시
public void updateGlobalPopularityVector() {
    log.info("Updating global popularity vector...");

    // GOOD 피드백이 많은 상위 20개 도서 추출
    List<Long> popularBookIds = feedbackRepository
        .findMostPopularBooks(FeedbackType.GOOD, PageRequest.of(0, 20));

    // 임베딩 조회 및 평균 계산
    List<float[]> embeddings = bookRepository.findEmbeddingsByIds(popularBookIds);
    if (embeddings.isEmpty()) {
        return;
    }
    float[] globalVector = VectorUtils.averageVector(embeddings.toArray(new float[0][]));

    // 캐싱 ("globalPopularity" 캐시 이름을 CacheConfig에 등록해야 함)
    cacheManager.getCache("globalPopularity").put("vector", globalVector);

    log.info("Global popularity vector updated: {} books", popularBookIds.size());
}
```

## 2. 성능 최적화

### 2.1 문제 분석

**성능 병목 지점:**

```
검색 요청
    ↓
[선호도 벡터 계산] ← 병목 1: DB 조회 + 평균 계산 (100-200ms)
    ↓
[기존 검색]       ← 병목 2: 키워드 + 벡터 검색 (50-100ms)
    ↓
[유사도 계산]      ← 병목 3: 각 도서별 코사인 유사도 (10-50ms)
    ↓
[재정렬]
    ↓
응답 (총 160-350ms)
```

**목표:** 응답 시간 100ms 이내

### 2.2 최적화 1: 선호도 벡터 캐싱

**Caffeine 캐싱:**

**캐시 구조 (userPreferenceVectors 캐시):**
```

```

**캐싱 효과:**
- 1회 계산: 150ms
- 캐시 히트: <5ms
- 약 30배 향상

### 2.3 최적화 2: 비동기 계산

**문제:** 피드백 저장 시 즉시 캐시를 무효화하면 검색이 지연됨

**해결:** 백그라운드에서 비동기로 계산

```java
@Service
public class PersonalizationServiceImpl implements PersonalizationService {

    @Async
    @CacheEvict(
        value = "userPreferenceVectors",
        key = "#chatId",
        cacheManager = "personalizationCacheManager"
    )
    public void evictUserPreferenceCacheAsync(Long chatId) {
        // 비동기로 캐시 무효화 (다음 요청 시 재계산)
        log.debug("Cache evicted asynchronously for chatId: {}",
            PrivacyUtil.maskChatId(chatId));
    }
}

@Service
@RequiredArgsConstructor
public class FeedbackServiceImpl implements FeedbackService {

    private final SearchFeedbackRepository searchFeedbackRepository;
    private final PersonalizationServiceImpl personalizationService;

    // 피드백 저장 시 호출
    @Transactional
    public SearchFeedback recordFeedback(Long chatId, FeedbackRequest request) {
        // 1. DB 저장 (동기)
        SearchFeedback saved = searchFeedbackRepository.save(
            SearchFeedback.of(chatId, request.query(), request.bookId(), request.type()));

        // 2. 캐시 무효화 (비동기) - 다른 빈을 거쳐 호출해야 @Async·@CacheEvict 프록시가 동작
        personalizationService.evictUserPreferenceCacheAsync(chatId);

        // 3. 즉시 응답 (지연 없음)
        return saved;
    }
}
```

### 2.4 최적화 3: 배치 처리

**문제:** 매일 새벽 전체 인기 벡터를 계산할 때 DB 부하 발생

**해결:** 배치로 분할 처리

```java
@Component
public class GlobalPopularityUpdater {

    @Scheduled(cron = "0 0 3 * * ?")
    public void updateGlobalPopularityVector() {
        int batchSize = 100;
        int offset = 0;

        float[] sumVector = null;
        int totalCount = 0;

        while (true) {
            // 배치로 조회 (BookRepository에 추가할 페이징 조회 메서드)
            List<float[]> batch = bookRepository
                .findEmbeddingsByGoodFeedbackBatch(offset, batchSize);

            if (batch.isEmpty()) break;

            // 누적 합계
            for (float[] embedding : batch) {
                if (sumVector == null) {
                    sumVector = embedding.clone();
                } else {
                    for (int i = 0; i < embedding.length; i++) {
                        sumVector[i] += embedding[i];
                    }
                }
                totalCount++;
            }

            offset += batchSize;
        }

        // 평균 계산 및 캐싱
        if (totalCount > 0) {
            for (int i = 0; i < sumVector.length; i++) {
                sumVector[i] /= totalCount;
            }
            cacheManager.getCache("globalPopularity").put("vector", sumVector);
        }
    }
}
```

## 3. 익명 사용자 환경 제약사항

### 3.1 Telegram chatId의 한계

**문제 1: Bot 삭제 후 재설치 → chatId 변경**

```
사용자 A: chatId = 12345
    → 피드백 20개 누적
    → 선호도 벡터 완성

[Bot 삭제 후 재설치]

사용자 A: chatId = 67890 (변경!)
    → 피드백 0개
    → 다시 콜드 스타트
```

**해결: 단기 세션으로 취급**

```java
// 6개월 이상 피드백이 없는 사용자 데이터 정리
@Scheduled(cron = "0 0 2 1 * ?")  // 매월 1일 새벽 2시
@Transactional
public void cleanupOldFeedbacks() {
    OffsetDateTime cutoff = OffsetDateTime.now().minusMonths(6);

    // SearchFeedbackRepository에 추가: long deleteByCreatedAtBefore(OffsetDateTime cutoff);
    long deleted = feedbackRepository.deleteByCreatedAtBefore(cutoff);

    log.info("Cleaned up old feedbacks: {} records", deleted);
}
```

**문제 2: 여러 기기에서 Bot 사용**

```
사용자 A: 스마트폰 (chatId=12345)
사용자 A: 태블릿   (chatId=12345)  ← 같은 chatId
사용자 A: 데스크톱 (chatId=12345)  ← 같은 chatId
```

**장점:** 자동으로 동기화됨 (Telegram 계정 연동)

**단점:** 가족이 계정을 공유하면 선호도가 섞임

### 3.2 데이터 보호

**PII(개인 식별 정보) 처리:**

```java
public class PrivacyUtil {

    private static final String SALT = "ai-library-telegram-salt-2025";

    /**
     * chatId를 해싱하여 로그에 안전하게 표시
     */
    public static String hashChatId(Long chatId) {
        if (chatId == null) {
            return null;
        }

        try {
            String input = chatId + SALT;
            MessageDigest digest = MessageDigest.getInstance("SHA-256");
            byte[] hash = digest.digest(input.getBytes(StandardCharsets.UTF_8));
            return Base64.getEncoder().encodeToString(hash);
        } catch (NoSuchAlgorithmException e) {
            throw new RuntimeException("해싱 알고리즘을 찾을 수 없습니다.", e);
        }
    }

    /**
     * chatId를 마스킹하여 로그에 표시
     */
    public static String maskChatId(Long chatId) {
        if (chatId == null) {
            return "null";
        }
        String chatIdStr = chatId.toString();
        if (chatIdStr.length() <= 3) {
            return "***";
        }
        return chatIdStr.substring(0, 3) + "***";
    }
}
```

**사용 예시:**
```java
log.info("Processing feedback for chatId: {}",
    PrivacyUtil.maskChatId(chatId));  // "123***"

log.info("Feedback stored for user: {}",
    PrivacyUtil.hashChatId(chatId));  // "a3f5b8c9d2e1..."
```

### 4.1 캐시 적중률 모니터링

```java
@Component
public class CacheMetrics {

    private final MeterRegistry meterRegistry;
    private final CacheManager cacheManager;

    // userPreferenceVectors 캐시는 개인화 전용 CacheManager에 있음
    public CacheMetrics(MeterRegistry meterRegistry,
                        @Qualifier("personalizationCacheManager") CacheManager cacheManager) {
        this.meterRegistry = meterRegistry;
        this.cacheManager = cacheManager;
    }

    @Scheduled(fixedRate = 60000)  // 1분마다
    public void reportCacheStats() {
        Cache cache = cacheManager.getCache("userPreferenceVectors");

        if (cache instanceof CaffeineCache caffeineCache) {
            com.github.benmanes.caffeine.cache.Cache<Object, Object> nativeCache =
                caffeineCache.getNativeCache();

            CacheStats stats = nativeCache.stats();  // CacheConfig에서 recordStats() 활성화 필요

            // 캐시 적중률 기록 (호출 시점의 통계를 읽도록 nativeCache에 바인딩)
            Gauge.builder("cache.hit_ratio", nativeCache, c -> c.stats().hitRate())
                .register(meterRegistry);

            log.info("Cache stats: hitRate={}, hitCount={}, missCount={}",
                stats.hitRate(), stats.hitCount(), stats.missCount());
        }
    }
}
```

## 5. 트러블슈팅

### 5.1 캐시가 너무 자주 만료됨

**증상:**
```
캐시 적중률: 10% (너무 낮음)
```

**원인:**
- 피드백 저장 시마다 캐시 무효화
- 피드백을 자주 남기는 사용자는 캐시 효과가 없음

**해결:** 캐시 만료 시간을 연장하고, 피드백 저장 시마다 `evictUserPreferenceCache()`를 호출하던 코드를 제거합니다.

```properties
# application.properties
# 캐시 만료 시간 연장 (24시간 → 7일)
cache.personalization.ttl.hours=168
```

**대신:** 주기적 배치로 갱신

```java
@Scheduled(cron = "0 0 */6 * * ?")  // 6시간마다
public void refreshAllUserPreferenceVectors() {
    // 활성 사용자(최근 7일 피드백)의 선호도 벡터 갱신
}
```

### 5.2 캐시 메모리 부족

Caffeine은 JVM 힙에 데이터를 저장하므로, 캐시 항목이 많아지면 힙 메모리를 압박합니다. 선호도 벡터 하나는 약 4KB(float 1024개)이므로 1000개면 약 4MB입니다.

**증상:**
```
java.lang.OutOfMemoryError: Java heap space
```

**해결:** TTL을 줄이거나 최대 캐시 수를 제한합니다.
```properties
# application.properties
# TTL (시간 단위)
cache.personalization.ttl.hours=24
# 최대 캐시 수
cache.personalization.max-size=1000
```

**null 값 캐싱 방지:** `@Cacheable`의 `unless = "#result == null"`로 콜드 스타트 사용자(null 결과)는 캐싱하지 않습니다.

```java
@Bean("personalizationCacheManager")
public CacheManager personalizationCacheManager() {
    CaffeineCacheManager cacheManager = new CaffeineCacheManager("userPreferenceVectors");
    cacheManager.setCaffeine(Caffeine.newBuilder()
        .expireAfterWrite(personalizationTtlHours, TimeUnit.HOURS)
        .maximumSize(personalizationMaxSize)   // 초과 시 오래 쓰지 않은 항목부터 제거
        .recordStats());
    return cacheManager;
}
```

1. **콜드 스타트 해결**
   - 최소 3개 피드백 요구
   - 전체 인기도 벡터 대안
   - 피드백 수집 유도

2. **성능 최적화**
   - Caffeine 캐싱 (30배 향상)
   - 비동기 계산으로 응답 시간 단축
   - 배치 처리로 DB 부하 감소

3. **익명 사용자 환경**
   - Telegram chatId 한계 이해
   - 단기 세션으로 취급
   - 6개월 데이터 정리
