# Phase 2: 사용자 선호도 벡터 계산

## 학습 개요

사용자가 과거에 GOOD 피드백을 남긴 도서들의 임베딩 벡터를 분석하여, 사용자의 선호도를 하나의 벡터로 표현하는 방법을 학습합니다. 벡터 평균 계산을 통해 사용자가 어떤 주제와 장르를 선호하는지 수학적으로 모델링합니다.

## 학습 목표

1. **사용자 선호도의 벡터 표현 이해**
   - 왜 벡터 평균이 사용자 취향을 나타내는가
   - GOOD 피드백 도서들의 선정 기준
   - 콜드 스타트 문제와 최소 피드백 수

2. **데이터 추출 및 필터링**
   - chatId로 사용자 피드백 조회
   - GOOD 타입 피드백만 필터링
   - 최근 N개 제한 및 중복 제거

3. **벡터 평균 계산 구현**
   - BookRepository 쿼리 작성
   - 벡터 평균 계산 알고리즘
   - 캐싱 전략으로 성능 최적화

## 1. 사용자 선호도 벡터의 개념

### 1.1 직관적 이해

**핵심 아이디어:** "사용자가 좋아한 도서들의 평균이 곧 사용자의 취향"

```
사용자 A가 좋아한 도서:
1. "해리포터와 마법사의 돌"    → embedding1: [0.5, 0.8, 0.3, ...]
2. "해리포터와 비밀의 방"      → embedding2: [0.6, 0.7, 0.4, ...]
3. "판타지 소설 모음집"        → embedding3: [0.4, 0.9, 0.2, ...]

사용자 A의 선호 벡터:
(embedding1 + embedding2 + embedding3) / 3
= [0.5, 0.8, 0.3, ...]  → "판타지", "마법", "모험" 키워드를 선호
```

**왜 평균인가?**

- **중심 경향성**: 여러 데이터의 대표값
- **잡음 감소**: 특정 도서의 편향성을 줄임
- **일반화**: 새로운 도서와 비교하기 쉬움

### 1.2 벡터 평균의 시각적 표현

```
       embedding2
          ↑
          │
          │
embedding1 └─→ avg_embedding ← ─ embedding3
          (선호도 중심)
```

**해석:**
- 세 벡터의 중심에 위치한 평균 벡터
- 이 평균 벡터에 가까운 도서 → 사용자가 좋아할 확률 높음
- 이 평균 벡터에서 먼 도서 → 사용자가 좋아할 확률 낮음

### 1.3 제약사항: 콜드 스타트 문제

**문제:** 신규 사용자는 피드백이 없어 선호도 계산 불가

```
신규 사용자: 피드백 0개
→ 평균 계산 불가
→ 개인화 제공 불가
```

**해결책: 최소 피드백 수 요구**

```java
if (좋아한 도서 수 < 3) {
    // 개인화 미적용 (일반 검색 결과 반환)
    return null;
}
```

**이유:**
- 1~2개는 우연일 가능성이 높음
- 3개 이상부터 일정한 패턴 형성
- 너무 많으면 최근성 반영 어려움 → 최근 20개 제한

## 2. 데이터 추출 파이프라인

### 2.1 전체 흐름도

```
[Step 1] 사용자 피드백 조회
    ↓
[Step 2] GOOD 타입 필터링
    ↓
[Step 3] 도서 ID 추출 및 중복 제거
    ↓
[Step 4] 최신순 정렬 및 TOP N 제한
    ↓
[Step 5] 임베딩 조회
    ↓
[Step 6] 벡터 평균 계산
    ↓
[사용자 선호도 벡터 완성]
```

### 2.2 단계별 상세 설명

#### Step 1: 사용자 피드백 조회

```java
// chatId로 사용자의 모든 피드백 조회
List<SearchFeedback> feedbacks =
    feedbackRepository.findByChatIdOrderByCreatedAtDesc(chatId);
```

**결과 예시:**
```
[
  {chatId: 12345, bookId: 101, type: GOOD, query: "해리포터"},
  {chatId: 12345, bookId: 102, type: BAD,  query: "주식"},
  {chatId: 12345, bookId: 101, type: GOOD, query: "해리포터"},  // 중복
  {chatId: 12345, bookId: 305, type: GOOD, query: "판타지"},
  ...
]
```

#### Step 2: GOOD 타입 필터링

```java
List<Long> likedBookIds = feedbacks.stream()
    .filter(f -> f.getType() == FeedbackType.GOOD)  // GOOD만
    .map(SearchFeedback::getBookId)
    .collect(Collectors.toList());
```

**결과 예시:**
```
[101, 305, 407, 512, 620, ...]
```

#### Step 3: 중복 제거

```java
.distinct()  // 같은 도서 여러 번 GOOD → 1번만 계산
```

**이유:**
- 사용자가 같은 도서를 여러 번 좋아할 수 있음
- 중복 제거로 특정 도서의 가중치 과대 방지

#### Step 4: 최신순 정렬 및 TOP N 제한

```java
.limit(20)  // 최근 20개만 사용
```

**이유:**
- 사용자 취향은 시간에 따라 변화
- 오래된 피드백보다 최근 피드백이 더 중요
- 너무 많으면 계산 비용 증가

#### Step 5: 임베딩 조회

```java
List<float[]> embeddings =
    bookRepository.findEmbeddingsByIds(likedBookIds);
```

**SQL 변환:**
```sql
SELECT embedding
FROM books
WHERE id IN (101, 305, 407, 512, 620);
```

**결과 예시:**
```
[
  [0.12, -0.34, 0.56, ..., 0.45],  // bookId=101
  [0.23, -0.45, 0.67, ..., 0.56],  // bookId=305
  [0.34, -0.56, 0.78, ..., 0.67],  // bookId=407
  ...
]
```

#### Step 6: 벡터 평균 계산

```java
float[] userPreferenceVector = calculateAverageVector(embeddings);
```

**계산 과정:**
```
입력: [
  [0.12, -0.34, 0.56, ..., 0.45],  // 1024차원
  [0.23, -0.45, 0.67, ..., 0.56],
  [0.34, -0.56, 0.78, ..., 0.67]
]

각 차원별 평균 계산:
result[0] = (0.12 + 0.23 + 0.34) / 3 = 0.23
result[1] = (-0.34 + -0.45 + -0.56) / 3 = -0.45
result[2] = (0.56 + 0.67 + 0.78) / 3 = 0.67
...
result[1023] = ...

출력: [0.23, -0.45, 0.67, ..., 0.56]  // 1024차원 평균 벡터
```

## 3. 구현

### 3.1 BookRepository 쿼리 추가

```java
public interface BookRepository extends JpaRepository<Book, Long> {

    /**
     * 도서 ID 목록으로 임베딩을 조회합니다.
     *
     * @param bookIds 도서 ID 목록
     * @return 임베딩 리스트 (float[1024][])
     */
    @Query("SELECT b.embedding FROM Book b WHERE b.id IN :bookIds AND b.embedding IS NOT NULL")
    List<float[]> findEmbeddingsByIds(@Param("bookIds") List<Long> bookIds);
}
```

**주의사항:**
- `IN` 쿼리는 목록 길이에 제약이 있을 수 있음 (PostgreSQL 기본 제한 없음)
- `bookIds`가 비어 있으면 빈 리스트 반환
- 임베딩이 없는(`NULL`) 도서는 제외됨
- 순서는 보장되지 않으므로 Map으로 매핑이 필요할 수 있음

### 3.2 PersonalizationService 구현

서비스는 인터페이스(`PersonalizationService`)와 구현체(`PersonalizationServiceImpl`)로 나누고, 선호도 벡터 계산과 캐싱은 별도 컴포넌트(`UserPreferenceVectorCalculator`)가 맡습니다. 최소/최대 피드백 수는 `application.properties`에서 조정할 수 있습니다.

**왜 계산 로직을 별도 빈으로 분리하는가?** Spring의 `@Cacheable`은 빈을 감싼 프록시가 메서드 호출을 가로채는 방식으로 동작합니다. 그래서 같은 클래스 안에서 `this.calculateUserPreferenceVector()`처럼 직접 호출하면(self-invocation) 프록시를 거치지 않아 캐시가 적용되지 않습니다. 03에서 만들 `personalizedSearch()`가 선호도 벡터를 내부에서 호출하므로, 캐시 대상 메서드를 다른 빈으로 옮겨 항상 프록시를 거치게 합니다.

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class UserPreferenceVectorCalculator {

    @Value("${app.personalization.min-feedback-count:3}")
    private int minFeedbackCount;   // 콜드 스타트 기준 (최소 3개)

    @Value("${app.personalization.max-feedback-count:20}")
    private int maxFeedbackCount;   // 최근 20개만 사용

    private final BookRepository bookRepository;
    private final SearchFeedbackRepository feedbackRepository;

    // 캐싱: 같은 사용자의 선호도 벡터를 24시간 동안 캐싱 (개인화 전용 CacheManager)
    @Cacheable(
        value = "userPreferenceVectors",
        key = "#chatId",
        unless = "#result == null",
        cacheManager = "personalizationCacheManager"
    )
    public float[] calculate(Long chatId) {
        // [Step 1-4] 좋아한 도서 ID 추출
        List<Long> likedBookIds = getLikedBookIds(chatId);

        // [콜드 스타트 체크] 최소 3개 이상이어야 개인화
        if (likedBookIds.size() < minFeedbackCount) {
            log.info("[PERSONALIZATION] Cold start for chatId: {} (feedback count: {})",
                chatId, likedBookIds.size());
            return null;
        }

        // [Step 5] 임베딩 조회
        List<float[]> embeddings = bookRepository.findEmbeddingsByIds(likedBookIds);

        if (embeddings.isEmpty()) {
            log.warn("[PERSONALIZATION] No embeddings found for chatId: {}", chatId);
            return null;
        }

        // [Step 6] 평균 계산
        float[] preferenceVector = VectorUtils.averageVector(embeddings.toArray(new float[0][]));

        log.info("[PERSONALIZATION] Preference vector calculated for chatId: {} (based on {} books)",
            chatId, embeddings.size());

        return preferenceVector;
    }

    /**
     * 선호도 벡터 캐시를 무효화합니다.
     * 새로운 피드백이 저장될 때 호출합니다.
     */
    @CacheEvict(
        value = "userPreferenceVectors",
        key = "#chatId",
        cacheManager = "personalizationCacheManager"
    )
    public void evict(Long chatId) {
        log.info("[PERSONALIZATION] Cache evicted for chatId: {}", chatId);
    }

    /**
     * 사용자가 좋아한 도서 ID 목록을 추출합니다.
     * - GOOD 피드백만
     * - 중복 제거
     * - 최신순 20개 제한
     */
    private List<Long> getLikedBookIds(Long chatId) {
        return feedbackRepository.findByChatIdOrderByCreatedAtDesc(chatId).stream()
            .filter(feedback -> feedback.getType() == FeedbackType.GOOD)
            .map(SearchFeedback::getBookId)
            .distinct()
            .limit(maxFeedbackCount)
            .collect(Collectors.toList());
    }
}
```

`PersonalizationServiceImpl`은 이 컴포넌트에 위임만 합니다.

```java
@Slf4j
@Service
@RequiredArgsConstructor
public class PersonalizationServiceImpl implements PersonalizationService {

    private final BookRepository bookRepository;
    private final UserPreferenceVectorCalculator userPreferenceVectorCalculator;

    @Override
    public float[] calculateUserPreferenceVector(Long chatId) {
        // 캐시가 적용되도록 별도 빈(프록시)을 통해 호출
        return userPreferenceVectorCalculator.calculate(chatId);
    }

    @Override
    public void evictUserPreferenceCache(Long chatId) {
        userPreferenceVectorCalculator.evict(chatId);
    }

    // personalizedSearch()는 03에서 구현
}
```

벡터 평균 계산은 `VectorUtils`의 정적 메서드로 분리합니다.

```java
/**
 * 벡터들의 평균 벡터를 계산합니다.
 *
 * @param vectors 벡터 배열 (각각 1024차원)
 * @return 평균 벡터 (1024차원)
 * @throws IllegalArgumentException 벡터 배열이 null이거나 비어 있는 경우, 또는 벡터 차원이 다른 경우
 */
public static float[] averageVector(float[][] vectors) {
    if (vectors == null || vectors.length == 0) {
        throw new IllegalArgumentException("Vectors cannot be null or empty");
    }

    int dimension = vectors[0].length;
    float[] result = new float[dimension];

    // 각 차원별로 합계 계산
    for (float[] vector : vectors) {
        if (vector.length != dimension) {
            throw new IllegalArgumentException("All vectors must have the same dimension");
        }
        for (int i = 0; i < dimension; i++) {
            result[i] += vector[i];
        }
    }

    // 평균 계산 (합계 / 개수)
    for (int i = 0; i < dimension; i++) {
        result[i] /= vectors.length;
    }

    return result;
}
```

### 3.3 캐싱 설정

이 프로젝트는 Caffeine 인메모리 캐시를 사용하며, 선호도 벡터에는 TTL과 최대 크기를 따로 지정한 전용 CacheManager(`personalizationCacheManager`)를 둡니다.

**application.properties**
```properties
# Personalization cache settings
cache.personalization.ttl.hours=24
cache.personalization.max-size=1000

# Personalization settings
app.personalization.min-feedback-count=3
app.personalization.max-feedback-count=20
```

**CacheConfig (개인화 캐시 부분):**
```java
@EnableCaching
@Configuration
public class CacheConfig {

    @Value("${cache.personalization.ttl.hours:24}")
    private int personalizationTtlHours;

    @Value("${cache.personalization.max-size:1000}")
    private int personalizationMaxSize;

    @Bean("personalizationCacheManager")
    public CacheManager personalizationCacheManager() {
        CaffeineCacheManager cacheManager = new CaffeineCacheManager("userPreferenceVectors");
        cacheManager.setCaffeine(Caffeine.newBuilder()
            .expireAfterWrite(personalizationTtlHours, TimeUnit.HOURS)  // 24시간 후 만료
            .maximumSize(personalizationMaxSize)                       // 최대 1000개 캐싱
            .recordStats());                                           // 통계 활성화
        return cacheManager;
    }
}
```

## 5. 테스트

### 5.1 단위 테스트

Repository를 Mockito로 대체하면 DB 없이도 선호도 계산 로직을 검증할 수 있습니다.

```java
@ExtendWith(MockitoExtension.class)
class UserPreferenceVectorCalculatorTest {

    @Mock
    private BookRepository bookRepository;

    @Mock
    private SearchFeedbackRepository feedbackRepository;

    @InjectMocks
    private UserPreferenceVectorCalculator calculator;

    private static final Long CHAT_ID = 12345L;

    @BeforeEach
    void setUp() {
        // @Value 필드는 Mockito가 주입하지 않으므로 직접 설정
        ReflectionTestUtils.setField(calculator, "minFeedbackCount", 3);
        ReflectionTestUtils.setField(calculator, "maxFeedbackCount", 20);
    }

    @Test
    void testCalculateUserPreferenceVector_EnoughFeedback() {
        // Given: chatId에 3개의 GOOD 피드백
        when(feedbackRepository.findByChatIdOrderByCreatedAtDesc(CHAT_ID))
            .thenReturn(List.of(
                SearchFeedback.of(CHAT_ID, "test", 101L, FeedbackType.GOOD),
                SearchFeedback.of(CHAT_ID, "test", 102L, FeedbackType.GOOD),
                SearchFeedback.of(CHAT_ID, "test", 103L, FeedbackType.GOOD)
            ));
        when(bookRepository.findEmbeddingsByIds(anyList()))
            .thenReturn(List.of(
                new float[]{1.0f, 2.0f, 3.0f},
                new float[]{3.0f, 4.0f, 5.0f},
                new float[]{5.0f, 6.0f, 7.0f}
            ));

        // When: 선호도 벡터 계산
        float[] preferenceVector = calculator.calculate(CHAT_ID);

        // Then: 각 차원의 평균 벡터 반환
        assertThat(preferenceVector).isEqualTo(new float[]{3.0f, 4.0f, 5.0f});
    }

    @Test
    void testCalculateUserPreferenceVector_ColdStart() {
        // Given: 피드백이 없는 사용자
        when(feedbackRepository.findByChatIdOrderByCreatedAtDesc(CHAT_ID))
            .thenReturn(new ArrayList<>());

        // When: 선호도 벡터 계산
        float[] preferenceVector = calculator.calculate(CHAT_ID);

        // Then: null 반환 (콜드 스타트)
        assertThat(preferenceVector).isNull();
    }

    @Test
    void testCalculateUserPreferenceVector_TwoFeedbacks() {
        // Given: 2개의 GOOD 피드백 (최소 3개 필요)
        when(feedbackRepository.findByChatIdOrderByCreatedAtDesc(CHAT_ID))
            .thenReturn(List.of(
                SearchFeedback.of(CHAT_ID, "test", 101L, FeedbackType.GOOD),
                SearchFeedback.of(CHAT_ID, "test", 102L, FeedbackType.GOOD)
            ));

        // When: 선호도 벡터 계산
        float[] preferenceVector = calculator.calculate(CHAT_ID);

        // Then: null 반환 (피드백 부족)
        assertThat(preferenceVector).isNull();
    }

    @Test
    void testAverageVector() {
        // Given
        float[][] vectors = {
            {1.0f, 2.0f, 3.0f},
            {4.0f, 5.0f, 6.0f},
            {7.0f, 8.0f, 9.0f}
        };

        // When
        float[] avg = VectorUtils.averageVector(vectors);

        // Then
        assertThat(avg).containsExactly(new float[]{4.0f, 5.0f, 6.0f}, within(0.001f));
    }
}
```

## 6. 성능 최적화

### 6.1 캐싱 전략

**문제:** 검색할 때마다 선호도 벡터를 계산하면 느림

**해결:** Caffeine 캐시에 24시간 캐싱

```java
// UserPreferenceVectorCalculator
@Cacheable(value = "userPreferenceVectors", key = "#chatId",
    unless = "#result == null", cacheManager = "personalizationCacheManager")
public float[] calculate(Long chatId) {
    // ... 계산 로직
}
```

**캐시 무효화 조건:**
1. 새로운 피드백 저장 시
2. 24시간 경과 후 자동 만료

```java
// 피드백 저장 시 캐시 무효화 (FeedbackServiceImpl.recordFeedback())
public SearchFeedback recordFeedback(Long chatId, FeedbackRequest request) {
    SearchFeedback saved = searchFeedbackRepository.save(
        SearchFeedback.of(chatId, request.query(), request.bookId(), request.type()));
    personalizationService.evictUserPreferenceCache(chatId);
    return saved;
}
```

### 6.2 비동기 계산 (선택 사항)

**문제:** 선호도 벡터 계산으로 검색 응답 시간이 지연됨

**해결:** 백그라운드에서 비동기로 계산

```java
@Async
public CompletableFuture<float[]> calculateUserPreferenceVectorAsync(Long chatId) {
    float[] vector = calculateUserPreferenceVector(chatId);
    return CompletableFuture.completedFuture(vector);
}
```

**사용 예시:**
```java
// 검색 결과 즉시 반환 (개인화 없이)
BookSearchResult result = bookSearchService.searchBooks(pageable, request);

// 백그라운드에서 선호도 계산
personalizationService.calculateUserPreferenceVectorAsync(chatId)
    .thenAccept(vector -> {
        // 다음 검색부터 반영
    });
```

## 학습 요약

### 핵심 개념

1. **사용자 선호도 벡터**
   - GOOD 피드백 도서들의 임베딩 평균
   - 사용자 취향의 중심을 나타내는 1024차원 벡터

2. **콜드 스타트 문제**
   - 신규 사용자는 피드백이 없어 개인화 불가
   - 해결: GOOD 피드백이 3개 이상일 때 개인화 시작

3. **데이터 추출 파이프라인**
   - GOOD 필터링 → 중복 제거 → 최신 20개 제한
   - 최근성 반영으로 변화하는 취향 적용

4. **성능 최적화**
   - 캐싱: 24시간 동안 선호도 벡터 저장
   - 캐시 무효화: 새 피드백 저장 시 갱신
