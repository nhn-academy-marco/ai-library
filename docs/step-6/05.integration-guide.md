# Phase 5: 전체 시스템 통합 가이드

## 학습 개요

Step 6 개인화 추천 시스템의 **전체 아키텍처와 구현 흐름**을 종합적으로 정리합니다. 각 컴포넌트 간의 상호작용, 데이터 흐름, 구현 체크리스트를 통해 시스템 전체를 이해하고 구현할 수 있도록 안내합니다.

## 학습 목표

1. **전체 아키텍처 이해**
   - 개인화 전후 시스템 비교
   - 각 컴포넌트의 역할과 책임
   - 데이터 흐름과 의존관계

2. **구현 단계별 체크리스트**
   - Phase별 구현 항목 점검
   - 순서별 구현 가이드
   - 완료 기준 정의

3. **테스트 시나리오**
   - 단위 테스트 전략
   - 통합 테스트 시나리오
   - 사용자 acceptance 테스트

4. **운영 모니터링**
   - 성능 지표(KPI) 정의
   - 모니터링 대상 선정
   - 알림 설정 가이드

| 컴포넌트 | 역할 | 입력 | 출력 |
|---------|------|------|------|

| **BookRepository** | 도서 임베딩 조회 | List\<Long\> ids | List\<float[]\> |

## 2. 데이터 흐름 상세 분석

### 2.1 선호도 벡터 계산 흐름

```
[트리거] 사용자가 검색 요청 (chatId: 12345)
    │
    ▼
[Step 1] PersonalizationService.calculateUserPreferenceVector(chatId)
    │
    ▼
[Step 2] Redis 캐시 확인
    │
    ├─ 캐시 히트?
    │   └─ YES → 선호도 벡터 반환 (종료)
    │
    └─ NO (캐시 미스)
        │
        ▼
[Step 3] FeedbackRepository 조회
    │ SELECT * FROM search_feedbacks
    │ WHERE chat_id = 12345
    │ AND type = 'GOOD'
    │ ORDER BY created_at DESC
    │ LIMIT 20
    │
    ▼
[Step 4] GOOD 피드백 도서 ID 추출
    │ bookIds = [101, 305, 407, 512, 620, ...]
    │
    ▼
[Step 5] 콜드 스타트 체크
    │
    ├─ bookIds.size() < 3?
    │   └─ YES → null 반환 (개인화 미적용)
    │
    └─ NO (3개 이상)
        │
        ▼
[Step 6] BookRepository 임베딩 조회
    │ SELECT embedding FROM books
    │ WHERE id IN (101, 305, 407, 512, 620, ...)
    │
    ▼
[Step 7] 벡터 평균 계산
    │ result[i] = (emb1[i] + emb2[i] + ...) / count
    │ for i = 0 to 1023
    │
    ▼
[Step 8] Redis에 캐싱 (TTL: 24시간)
    │ key: "userPreferenceVectors::12345"
    │ value: float[1024]
    │
    ▼
[완료] 선호도 벡터 반환
```

### 2.2 개인화 재정렬 흐름

```
[입력] 기존 검색 결과 (topK=10)
    [
      {id: 1, title: "Effective Java", score: 0.035, embedding: [...]},
      {id: 2, title: "스프링 부트入门", score: 0.025, embedding: [...]},
      {id: 3, title: "자바 성능 튜닝", score: 0.020, embedding: [...]},
      ...
    ]
    │
    ▼
[Step 1] 사용자 선호도 벡터 확인
    │
    ├─ 선호도 벡터 있음?
    │   └─ YES → 계속 진행
    │
    └─ null
        └─ 기존 결과 그대로 반환 (종료)
    │
    ▼
[Step 2] 각 도서별 코사인 유사도 계산
    │
    ├─ 도서 1: cosine_similarity(preference, embedding1) = 0.40
    ├─ 도서 2: cosine_similarity(preference, embedding2) = 0.85
    ├─ 도서 3: cosine_similarity(preference, embedding3) = 0.75
    └─ ...
    │
    ▼
[Step 3] 최종 점수 계산
    │
    ├─ 도서 1: finalScore = 0.035 + (0.40 × 0.3) = 0.155
    ├─ 도서 2: finalScore = 0.025 + (0.85 × 0.3) = 0.280
    ├─ 도서 3: finalScore = 0.020 + (0.75 × 0.3) = 0.245
    └─ ...
    │
    ▼
[Step 4] 재정렬 (내림차순)
    │
    ▼
[출력] 개인화된 검색 결과
    [
      {id: 2, title: "스프링 부트入门", finalScore: 0.280, personalization: 0.85},
      {id: 3, title: "자바 성능 튜닝", finalScore: 0.245, personalization: 0.75},
      {id: 1, title: "Effective Java", finalScore: 0.155, personalization: 0.40},
      ...
    ]
```

```
- 개인화 미적용
- 기존 검색 결과 그대로
- 안내 메시지: "더 좋은 추천을 위해 피드백을 남겨주세요"
```

**시나리오 2: 개인화 적용 사용자**

```
[Given]
- chatId: 12345
- 피드백: 5개 (웹 개발 관련 도서들)

[When]
- 검색어: "자바"

[Then]
- 개인화 적용됨
- 스프링, 웹 프레임워크 관련 도서 상위 노출
- 안내 메시지: "✨ 개인화된 추천이 적용되었습니다!"
- 각 도서에 "💝 선호도: XX.XX%" 표시
```

**시나리오 3: 캐시 동작**

```
[Given]
- chatId: 12345
- 1회 검색 완료 (선호도 벡터 캐싱됨)

[When]
- 2회 검색 (같은 chatId)

[Then]
- DB 조회 없이 캐시에서 선호도 벡터 반환
- 응답 시간 단축 (< 10ms)
```

### 4.3 사용자 Acceptance 테스트

**테스트 절차:**

1. **신규 사용자로 시작**
   - Bot 시작 (`/start`)
   - 검색어 입력: "판타지"
   - 확인: 일반 검색 결과만 표시

2. **피드백 3개 남기기**
   - 검색 결과에서 3개 도서에 👍 클릭
   - 확인: "🎉 개인화된 추천이 시작되었습니다!" 메시지

3. **개인화 확인**
   - 같은 검색어로 재검색: "판타지"
   - 확인: 이전에 좋아한 도서와 유사한 도서 상위 노출
   - 확인: "✨ 개인화된 추천" 메시지

4. **선호도 변경**
   - 다른 주제 검색: "주식 투자"
   - 👍 피드백 5회 이상 남기기
   - 확인: 주식 관련 도서도 추천에 포함

```java
@Scheduled(cron = "0 0 2 1 * ?")  // 매월 1일 새벽 2시
```
