# Phase 5: 전체 시스템 통합 가이드

## 학습 개요

Step 6 개인화 추천 시스템의 전체 아키텍처와 구현 흐름을 종합적으로 정리합니다. 각 컴포넌트 간의 상호작용, 데이터 흐름, 구현 체크리스트를 통해 시스템 전체를 이해하고 구현할 수 있도록 안내합니다.

## 학습 목표

1. **전체 아키텍처 이해**
   - 개인화 전후 시스템 비교
   - 각 컴포넌트의 역할과 책임
   - 데이터 흐름과 의존 관계

2. **구현 단계별 체크리스트**
   - Phase별 구현 항목 점검
   - 순서별 구현 가이드
   - 완료 기준 정의

3. **테스트 시나리오**
   - 단위 테스트 전략
   - 통합 테스트 시나리오
   - 사용자 인수(Acceptance) 테스트

4. **운영 모니터링**
   - 성능 지표(KPI) 정의
   - 모니터링 대상 선정
   - 알림 설정 가이드

## 2. 데이터 흐름 상세 분석

### 2.1 선호도 벡터 계산 흐름

```
[트리거] 사용자가 검색 요청 (chatId: 12345)
    │
    ▼
[Step 1] UserPreferenceVectorCalculator.calculate(chatId)
    │
    ▼
[Step 2] Caffeine 캐시 확인 (personalizationCacheManager)
    │
    ├─ 캐시 히트?
    │   └─ YES → 선호도 벡터 반환 (종료)
    │
    └─ NO (캐시 미스)
        │
        ▼
[Step 3] SearchFeedbackRepository 조회
    │ SELECT * FROM search_feedbacks
    │ WHERE chat_id = 12345
    │ ORDER BY created_at DESC
    │
    ▼
[Step 4] GOOD 피드백 도서 ID 추출 (Java Stream)
    │ GOOD 필터링 → 중복 제거 → 최대 20개
    │ bookIds = [101, 305, 407, 512, 620, ...]
    │
    ▼
[Step 5] 콜드 스타트 체크
    │
    ├─ bookIds.size() < 3?
    │   └─ YES → null 반환 (개인화 미적용)
    │
    └─ NO (3개 이상)
        │
        ▼
[Step 6] BookRepository 임베딩 조회
    │ SELECT embedding FROM books
    │ WHERE id IN (101, 305, 407, 512, 620, ...)
    │
    ▼
[Step 7] 벡터 평균 계산
    │ result[i] = (emb1[i] + emb2[i] + ...) / count
    │ for i = 0 to 1023
    │
    ▼
[Step 8] Caffeine 캐시에 저장 (TTL: 24시간)
    │ cache: "userPreferenceVectors", key: 12345
    │ value: float[1024]
    │
    ▼
[완료] 선호도 벡터 반환
```

### 2.2 개인화 재정렬 흐름

```
[입력] 기존 검색 결과 (topK=10)
    [
      {id: 1, title: "Effective Java", score: 0.035, embedding: [...]},
      {id: 2, title: "스프링 부트 입문", score: 0.025, embedding: [...]},
      {id: 3, title: "자바 성능 튜닝", score: 0.020, embedding: [...]},
      ...
    ]
    │
    ▼
[Step 1] 사용자 선호도 벡터 확인
    │
    ├─ 선호도 벡터 있음?
    │   └─ YES → 계속 진행
    │
    └─ null
        └─ 기존 결과 그대로 반환 (종료)
    │
    ▼
[Step 2] 각 도서별 코사인 유사도 계산
    │
    ├─ 도서 1: cosine_similarity(preference, embedding1) = 0.40
    ├─ 도서 2: cosine_similarity(preference, embedding2) = 0.85
    ├─ 도서 3: cosine_similarity(preference, embedding3) = 0.75
    └─ ...
    │
    ▼
[Step 3] 최종 점수 계산
    │
    ├─ 도서 1: finalScore = 0.035 + (0.40 × 0.3) = 0.155
    ├─ 도서 2: finalScore = 0.025 + (0.85 × 0.3) = 0.280
    ├─ 도서 3: finalScore = 0.020 + (0.75 × 0.3) = 0.245
    └─ ...
    │
    ▼
[Step 4] 재정렬 (내림차순)
    │
    ▼
[출력] 개인화된 검색 결과
    [
      {id: 2, title: "스프링 부트 입문", finalScore: 0.280, personalization: 0.85},
      {id: 3, title: "자바 성능 튜닝", finalScore: 0.245, personalization: 0.75},
      {id: 1, title: "Effective Java", finalScore: 0.155, personalization: 0.40},
      ...
    ]
```

```java
@Configuration
public class CacheConfig {

        CaffeineCacheManager manager = new CaffeineCacheManager("userPreferenceVectors");
        manager.setCaffeine(Caffeine.newBuilder()
            .expireAfterWrite(personalizationTtlHours, TimeUnit.HOURS)
            .maximumSize(personalizationMaxSize)
            .recordStats());
        return manager;
    }
}
```

**구현 항목:**

## 6. 운영 가이드

### 6.1 캐시 관리

Caffeine은 애플리케이션 메모리 안의 캐시이므로, 애플리케이션을 재시작하면 모두 비워집니다. 실행 중에는 코드로 관리합니다.

**캐시 초기화:**
```java
// 특정 사용자만 삭제
personalizationService.evictUserPreferenceCache(12345L);

// 전체 삭제
personalizationCacheManager.getCache("userPreferenceVectors").clear();
```

**캐시 크기 모니터링:**
```java
CaffeineCache cache = (CaffeineCache) personalizationCacheManager.getCache("userPreferenceVectors");
long size = cache.getNativeCache().estimatedSize();       // 현재 항목 수
double hitRate = cache.getNativeCache().stats().hitRate(); // 적중률 (recordStats() 필요)
```

### 6.2 데이터 정리

**오래된 피드백 삭제:**
```sql
-- 6개월 이상 피드백 삭제
DELETE FROM search_feedbacks
WHERE created_at < NOW() - INTERVAL '6 months';
```

**또는 배치로:**
```java
@Scheduled(cron = "0 0 2 1 * ?")  // 매월 1일 새벽 2시
public void cleanupOldFeedbacks() {
    LocalDateTime cutoff = LocalDateTime.now().minusMonths(6);
    int deleted = feedbackRepository.deleteByCreatedAtBefore(cutoff);
    log.info("Cleaned up old feedbacks: {} records", deleted);
}
```

### 6.3 장애 대응

**장애 상황:** 선호도 벡터 계산 실패 (DB 조회 오류 등)

**대응:**
1. 개인화를 건너뛰고 기존 검색 결과만 반환 (fallback)
2. 오류 로그로 원인 확인
3. 복구 후 다음 요청부터 자동으로 재계산·캐싱

```java
@Cacheable(
    value = "userPreferenceVectors",
    key = "#chatId",
    unless = "#result == null",
    cacheManager = "personalizationCacheManager"
)
// Fallback: 계산 실패 시 null 반환 → personalizedSearch()가 기존 검색 결과를 그대로 반환
// (UserPreferenceVectorCalculator)
public float[] calculate(Long chatId) {
    try {
        // ... 계산 로직
    } catch (Exception e) {
        log.error("Failed to calculate preference vector, skipping personalization", e);
        return null;
    }
}
```
